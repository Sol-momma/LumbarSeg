# SPIDER 全447系列での「55%フィルター」集計（CPU、2026-10-21）

学習はしていません。CPU の pod（RunPod cpu3c・4 vCPU）で、ボリューム上の SPIDER 全447系列（images・masks の MHA）を [`scripts/count_filter_all.py`](../../scripts/count_filter_all.py) で数えました。数字はすべて実測です（エラー0件）。
スライスの作り方は前処理（`extract_slices`）と同じです。最も小さい軸を矢状断とし、画素値が一定のスライスは除き、ラベルを4クラスにして、マスクを 512×640 に最近傍で縮小しています。

## 2. 読み取り

- 34枚しか残らないのは、T2 SPACE だけを使っているせいではありませんでした。現実装の読み方（A）だと、全系列を合わせても 101 枚（T1 27・T2 40・T2 SPACE 34）しか残りません。
- 論文の Table 1 の「T1・T2・T2 SPACE が各1000枚」に合うのは、フィルターがほとんど何も除かない読み方（A90・C・F）に、系列ごとの1000枚上限を組み合わせた場合です。4クラスのそろうスライスは T1 1626・T2 1699・T2 SPACE 1449 で、どれも1000枚を超えるので、上限をかけるとそれぞれちょうど1000枚になります。
- 「最大が最小の55倍以下」（G）は T1 451・T2 505・T2 SPACE 810 で、1000枚に届きません。
- B・D・E はどの系列でも0枚です。
- 論文の比率の数字（57%・56%・40% など）は、どの読み方でも再現できませんでした（平均 class weight から作る比も合いません）。
