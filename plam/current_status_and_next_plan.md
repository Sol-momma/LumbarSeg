# LumbarSeg 現状整理と次の実行プラン

更新日: 2026-08-02

## 結論

LumbarSeg は、データ確認、前処理、学習、評価、予測画像の表示までの基盤が完成している。
現在は論文再現の途中であり、次は T1、T2、T2 SPACE をまとめた比較実験を行う。

研究室 PC の WSL は応答しない状態のため、当面は Google Colab GPU を第一候補とする。
WSL の強制終了や PC の再起動は、研究室の管理者による許可または対応後に行う。

## 研究の目的

Ahmed et al. (2025) の腰椎 MRI セグメンテーションを再現し、論文で報告された Dice 約 `0.97` に近い結果を確認する。
再現条件と評価方法を確定した後、モデルや損失関数を改良して論文値を上回ることを目指す。

## 完了していること

- SPIDER 全データの取得と構成確認
  - 218 patients
  - T1: 196 series
  - T2: 210 series
  - T2 SPACE: 41 series
  - 合計: 447 series
- 3D MHA から 2D sagittal slice を作成する前処理
- 4クラスのラベル変換
  - Background
  - Vertebrae
  - Spinal Canal
  - IVDs
- Modified U-Net の実装
- Focal Loss と Dice Loss を組み合わせた損失関数の実装
- 学習、クラス別評価、予測画像表示の実装
- 軽量な実験結果を `docs/experiments/` に記録する仕組み
- T2 および T2 SPACE を使った基準実験

関連資料:

## 現在の基準結果

最新の T2 SPACE 実験結果は次のとおり。

| 指標 | 現在値 | 論文目標 |
| --- | ---: | ---: |
| Mean Dice | 0.8836 | 約 0.97 |
| Vertebrae Dice | 0.9182 | 0.9712 |
| Spinal Canal Dice | 0.7859 | 0.9671 |
| IVD Dice | 0.8451 | 0.9688 |

脊柱管の精度が最も低く、今後の原因確認で優先して見る。

## 現在の未完了事項

- T1、T2、T2 SPACE をまとめた比較実験
- 論文と同じ学習対象、データ分割、評価方法になっているかの最終確認
- 精度が低い画像の抽出と原因分類
- 改良方法の決定
- 改良モデルと基準モデルの比較

論文が3種類の MRI を別々に学習したのか、まとめて学習したのかは未確定である。
そのため、次の全データ実験は条件を切り分けるための比較実験として扱い、この結果だけで論文再現完了とは判断しない。

- WSL の通常起動が応答しない
- WSL 管理サービスの通常再起動も完了しない
- 実験結果の消失はない

## 次の実行プラン

### Phase 1: 実行環境を決める

推奨: Google Colab GPU を使用する。

確認事項:

- Google Drive の `/content/drive/MyDrive/SPIDER/DataSet/` にデータがある
- `images/`、`masks/`、overview CSV が揃っている
- Colab から GPU が1台以上見える

代替案:

- 研究室の管理者に WSL の復旧を依頼し、復旧後に研究室 PC の GPU を使う
- Windows 直接実行は可能だが、古い TensorFlow、CUDA、cuDNN の組み合わせが必要なため第二候補とする

完了条件:

- 使用する環境を1つに決める
- GPU が認識される
- データと出力先へアクセスできる

### Phase 2: 1 epoch の動作確認

本学習の前に、全シーケンス条件で1 epochだけ実行する。

予定条件:

| 項目 | 値 |
| --- | --- |
| 対象 | T1、T2、T2 SPACE |
| 必要クラス数 | 4 |
| クラス偏りの上限 | 0.90 |
| 各シーケンスの上限 | 1000 slices |
| Batch size | 2 |
| Epochs | 1 |

完了条件:

- 学習用と検証用の画像が0件ではない
- GPUを使って1 epochが最後まで完了する
- `best_model.keras` と `training_log.csv` が新しく作成される
- エラーなく評価まで実行できる

### Phase 3: 全シーケンスの本学習

Phase 2 と同じ条件で、最大100 epochの本学習を行う。
検証精度が改善しなくなった場合は早期終了を使用する。

予定する実験名:

```text
all_sequences_reproduction_4cls090_cap1000
```

完了条件:

- 学習が早期終了または100 epochまで完了する
- 実行時の条件とログが保存される
- `best_model.keras`、`training_log.csv`、`validation_metrics.csv` が新規生成される
- 新しく生成した結果だけを合否判断に使う

### Phase 4: 結果を比較する

比較対象:

1. T2 SPACE 単独の現在値
2. T1、T2、T2 SPACE をまとめた新しい結果
3. 論文のクラス別 Dice

優先して確認すること:

- Mean Dice が `0.8836` から改善したか
- Spinal Canal Dice が `0.7859` から改善したか
- Vertebrae、Spinal Canal、IVDs のすべてが安定して学習されているか
- 学習用と検証用の患者が重複していないか

完了条件:

- 同じ形式の比較表を作成する
- 改善、悪化、判断保留を指標ごとに記録する
- 論文値との差を説明できる

### Phase 5: 精度が低い画像を確認する

新しいモデルの予測を MRI に重ねて表示し、精度が低い画像を優先して確認する。

原因分類:

- MRI の向き、回転、反転
- 前処理やラベル変換
- クラスの偏り
- 学習不足
- 判定不能

完了条件:

- 代表的な成功例と失敗例を保存する
- 脊柱管の精度低下について原因候補を記録する
- 次に変更する対象を1つに絞る

### Phase 6: 改良段階へ進むか判断する

論文再現条件に大きな未確認点が残る場合は、改良実装を始めず、次の順で差を調べる。

1. 患者単位の学習・検証分割
2. MRI の向きと回転
3. スライス選択条件
4. 学習条件
5. 評価方法

再現条件を説明できる状態になったら、Attention U-Net、Boundary Loss、データ拡張などの改良候補から1つを選ぶ。
